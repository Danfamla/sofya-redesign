# Публикация демонстрационной версии на GitHub Pages

## До публикации

1. Получите письменное разрешение правообладателя на публичное использование фотографий, текстов и названия «Софья».
2. Проверьте у студии актуальность адреса, графика, гарантийных сроков и сроков изготовления.
3. Не публикуйте проект как официальный сайт, пока студия не утвердила материалы и размещение.

## GitHub Pages из репозитория

1. Создайте новый **private** репозиторий на GitHub.
2. Загрузите **содержимое** папки `sofya-redesign` в корень репозитория: `index.html`, `styles.css`, `enhancements.css`, `final-polish.css`, `script.js` и папку `assets`.
3. В репозитории откройте **Settings → Pages**.
4. В разделе **Build and deployment** выберите **Deploy from a branch**.
5. Выберите ветку `main` и папку `/(root)`, затем сохраните.
6. Дождитесь публикации и откройте адрес из блока GitHub Pages.

## Почему сайт работает в подпапке

В проекте используются относительные пути (`assets/...`, `styles.css`, `script.js`) и якорные ссылки (`#catalog`): они работают как в корне домена, так и в URL формата `https://username.github.io/repository-name/`.

## Проверка после публикации

1. Откройте главную в обычном и мобильном браузере.
2. Откройте все 12 карточек каталога и закройте модальное окно фото.
3. Проверьте кнопки каталога, контактов и «Обсудить проект».
4. Убедитесь, что форма сообщает об отсутствии отправки.
5. Откройте инструменты разработчика и убедитесь, что в Console и Network нет ошибок загрузки.

> GitHub Pages публичен для опубликованного сайта. Пока разрешение правообладателя не получено, ограничьте доступ к репозиторию и распространяйте архив только напрямую потенциальному клиенту.
